# ADR 0008: 계정 삭제의 로컬 데이터와 외부 주문 경계

- 상태: 승인
- 날짜: 2026-09-06

## 배경

사용자는 자신의 설정과 모의투자 데이터를 삭제할 수 있어야 한다. 하지만 증권사에
전달된 주문은 로컬 데이터만 지우면 처리 결과를 추적하거나 대사할 수 없게 된다.
DB의 여러 테이블을 순서대로 지우는 도중 실패할 때 일부 데이터만 남는 문제도
피해야 한다.

## 결정

- `DELETE /api/v1/me`는 본인 인증과 본문의 `{"confirmation":"DELETE"}`를
  요구한다.
- 사용자 설정, 모의 계좌, 주문, 체결, 상태 이력, 현금 원장, 포지션과 스냅샷은
  하나의 DB 트랜잭션에서 삭제한다.
- 브로커 주문이 모두 `cancelled`일 때만 관련 주문과 outbox 기록을 함께 삭제한다.
- 제출 대기, 제출 완료, 취소 대기 또는 대사 필요 주문이 있으면 `409 Conflict`로
  전체 삭제를 차단한다.
- 같은 삭제 요청을 반복해도 성공하며 삭제된 행 수는 0을 반환한다.
- Supabase Auth 사용자의 제거는 인증 시스템의 별도 보안 경계로 남긴다. 이 API는
  애플리케이션 DB의 데이터 삭제만 책임진다.

## 이유

모의투자 기록은 실제 금융 거래 원장이 아니므로 사용자의 삭제 요청을 우선할 수
있다. 반면 상태가 확정되지 않은 외부 주문 기록을 지우면 중복 주문 또는 미확인
체결을 복구할 근거가 사라진다. 미확정 주문을 먼저 대사하도록 강제하면 개인정보
삭제와 주문 안전성을 명시적으로 분리할 수 있다.

## 결과와 한계

- 외래 키 순서와 관계없이 DB cascade에 의존하지 않고 삭제 대상을 코드에서
  명시한다.
- 중간 실패는 전체 롤백되며 다른 사용자의 데이터는 조회하거나 삭제하지 않는다.
- 외부 인증 계정까지 한 요청에서 지우지는 않는다. 운영에서는 Supabase의 관리자
  권한을 백엔드에 직접 노출하지 않는 별도 탈퇴 완료 절차가 필요하다.
